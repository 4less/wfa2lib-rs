What changed

Speed v1–v18

  • WF-adaptive cutoff without a distance buffer, then a vectorised reduce scan and an AVX2 min-distance pass.
  • Wavefront pads nulled at allocation (AVX2 fill, pads only, one dispatch for the three outputs) instead of per-step init.
  • Gap-affine kernel: no scalar tail, inlined, AVX-512VL bounds check; compute step specialised on memory mode.
  • Ends-free: one-pass termination, begin-free init as fill plus identity ramp; 32-byte extend compares.
  • Trimming within the input hull; three-in-one output allocation.

Memory v7, v21–v24

  • CIGAR-mode wavefronts sized by need, rounded to 16 elements; headroom only below 1024 elements.
  • Per-score component arrays capped at the step limit.
  • Arena starts at 64 KB and grows geometrically to 1 MB chunks; null and victim wavefronts start at ±256.

Correctness v24–v25

  • Null-wavefront range (v24): resizing a 1-wide range proposed a bound outside the null wavefront, so the kernel read freed memory. The same arithmetic is latent in C.
  • Null-step accounting and null-input substitution: ported from C. Root cause of the banded and X-drop crashes and the end-only ends-free differences.
  • Match-reward ends-free diagonals (C's wavefront_compute_endsfree_*) were missing.
  • Ends-free termination order now follows the SIMD lane count the build targets, as the C kernel does.
  • Exact input-range union with null inputs, and the BiWFA unreachable check on a null base.

The v25 A/B record is flagged as a checksum change on the dovetail workload only. That is the intended effect of the ends-free termination-order fix: the alignment score is unchanged and the reported end point now matches C for the SIMD width of the build.

Remaining differences vs C (226 configs)

  • Gap-affine with match reward (62 configs): global, ends-free and extension outputs differ from C. The ends-free diagonal port fixed about 100 configs; the remaining ones need the same treatment in the main loop.
  • Gap-affine with penalties 0/3/1/4 (26): ends-free, global and extension ties; includes the two X-drop pairs on short_e05 (one tie-break, one where C stops at −22 vs our −19).
  • Banded, band-adaptive and Z-drop on edit, indel, linear and gap-affine penalties (about 100): a different pruning path, no crashes.
  • End-only ends-free ties (about 30): one or two pairs per 2000 where C picks another optimal end point; exact DP shows C suboptimal in several.
  • Still crashing (4): gap-affine 2-piece with a static or adaptive band in CIGAR mode on short_e20 and utest (segfault). BiWFA with heuristics (12) no longer crashes but differs.
