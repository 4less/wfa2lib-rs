Index lookups, checked on reads that should all map

Two datasets that pull in opposite directions. In bacteroides, every read comes from the 249 reference genomes (1,991,540 reads). In protal-mini, 95% of pairs map nowhere. Contenders: flexalign main@7ea91cf (original), the speed branch with wfa2lib-rs (f0831c4, base), this work (index-lookup@85b4350, tag perf/v4-index-lookup), and minibwa 0.7-r421. Update 2026-10-25: the later milestones perf/v5-lookup2 (cab17fa), perf/v6-syncmer (8ade5a8) and perf/v8-single-end (97b81cc, now main; its paired-end code is v7's anchor work) are added below; details on the Index Lookup Round 2 page.

Wall time (median of 5 runs, minibwa 3)

v4 to v8 were re-measured on 2026-10-25; the other bars are from the original round.

All runs share one page-cache state, with the indexes in 2 MB folios, and the index is warmed before each run. With 4 KB folios, before I collapsed the cache, the same change measured 0.92 → 0.82 s (−11%) on bacteroides and 1.51 → 1.46 s (−3%) on protal-mini.

What I found along the way

  • Page-table walks, not DRAM, held up the prefetches. With --index-mmap, the index sits in the page cache in 4 KB pages. Every random value prefetch then needs a page walk, and 12% of lookup stalled on the prefetch instruction. Once the index's page cache was rebuilt into 2 MB folios with MADV_COLLAPSE, that stall fell to 4.6%. Both builds got faster: bacteroides 0.82 → 0.76 s, protal-mini 1.46 → 1.43 s. Collapsing takes 0.4–1.2 s once per index and lasts until the cache is evicted.
  • Most of a lookup is now its own work. A warm repeat of every lookup adds 1.0 s of CPU to protal-mini, out of about 3 s spent in lookup. A one-pair lookahead across the worker loop could hide most of the remaining misses. It needs an owned copy of the next pair, because bioreader lends records only for the length of the callback.
  • The build has no popcnt. count_ones compiles to a bit-twiddling sequence under the current target features. It doesn't cost measurable time today; the fast path no longer counts bits at all.

Run details

  • Machine: AMD Ryzen AI 9 HX 370, 24 threads, Linux 7.2. Builds use nightly Rust, fat LTO and AVX2. minibwa runs map -x sr.
  • Tests: 93 pass. The only failure is test_offset_similarities, which also fails on main.
  • flexmap, bioreader and kmerrs are unchanged. The change lives in flexalign: range_extractor.rs, seed_extractor.rs, modular_workflow.rs, and a prefetch_keys hook on the database trait.
